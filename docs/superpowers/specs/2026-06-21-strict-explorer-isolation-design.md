# Строгое отключение Explorer

## Цель

Вернуть завершение `explorer.exe` при любом запуске киоска, включая ручной запуск EXE, не меняя остальную рабочую логику, интерфейс, защиту клавиатуры и надзор разрешенного приложения.

## Поведение

- При переходе в операторский режим киоск завершает только процессы `explorer.exe` текущей пользовательской сессии.
- Контроль остается активным в операторском режиме и в окне авторизации. Если Windows снова запускает Explorer в этой сессии, киоск завершает новый экземпляр.
- Процессы Explorer других пользовательских сессий не затрагиваются.
- Успешная авторизация администратора не запускает Explorer автоматически.
- Explorer запускается обратно только после успешного Restore либо при штатном выходе из киоска.
- Службы, драйверы, автозагрузка, системные процессы и процессы других пользователей не изменяются.

## Изменение архитектуры

Существующий `DesktopIsolation` уже умеет выполнять строгую изоляцию с фильтрацией по текущей сессии. Меняется только композиция launcher: строгий режим передается всегда, без выбора hide-only fallback по значению текущей shell в реестре.

Модули управления разрешенным приложением, окнами, клавиатурой, авторизацией и интерфейсом не меняются.

## Восстановление

Restore использует существующий механизм восстановления shell и запускает не более одного `explorer.exe`. При штатном выходе launcher снимает keyboard hook, прекращает изоляцию, восстанавливает скрытые поверхности и запускает Explorer. Простая успешная авторизация администратора не считается восстановлением и Explorer не запускает.

## Проверка

1. Новый регрессионный тест подтверждает, что ручной запуск launcher включает `terminate_explorer=True`.
2. Тесты подтверждают фильтрацию Explorer по текущей сессии.
3. Тесты подтверждают отсутствие запуска Explorer после одной лишь успешной авторизации.
4. Полностью запускаются modern, legacy и parity-наборы тестов.
5. Пересобираются Modern и Legacy EXE.
6. В живом тесте проверяются завершение Explorer, работа разрешенного приложения и восстановление рабочего стола после штатного выхода/Restore.

## Ограничение

При ручном запуске под учетной записью, где Windows настроена запускать `explorer.exe` как shell, Windows может пытаться перезапускать Explorer. Киоск будет завершать каждый новый экземпляр только в текущей сессии. Это является намеренным строгим поведением и может кратковременно влиять на фокус окна на такой тестовой учетной записи.
