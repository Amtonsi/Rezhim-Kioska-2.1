# Выбор разрешенного приложения при первом запуске

## Цель

Киоск должен безопасно запускать оболочку даже тогда, когда разрешенное приложение еще не выбрано или сохраненный EXE отсутствует. Выбор выполняется только после успешной локальной авторизации администратора Windows через существующую кнопку изменения приложения. Результат сохраняется и используется после перезапуска или выключения компьютера.

## Подтвержденная причина ошибки

Предоставленная конфигурация содержит путь `F:\Telegram Desktop\Telegram.exe`. На тестовой Windows 7 файла по этому пути нет. Текущий bootstrap вызывает загрузку конфигурации с `require_existing_app=True`, поэтому завершается до создания окна киоска с ошибкой `file_not_found`.

## Состояния конфигурации

В `allowedApplication` добавляется необязательное логическое поле `configured`.

- Свежая конфигурация содержит `configured: false` и всегда требует первоначального выбора.
- После успешного выбора Configurator сохраняет `configured: true`, новый абсолютный путь EXE и его рабочую папку.
- Старые конфигурации без поля `configured` считаются настроенными для обратной совместимости.
- Если настроенный EXE отсутствует, runtime независимо от значения поля переходит в безопасное состояние «Приложение не настроено».

## Запуск киоска

Bootstrap проверяет структуру и Windows-семантику JSON, но не требует наличия разрешенного файла до создания оболочки. Затем композиция выбирает один из двух адаптеров приложения:

- `ObservedApplication` для существующего настроенного EXE;
- `UnconfiguredApplication` для первоначальной настройки или отсутствующего EXE.

`UnconfiguredApplication` реализует тот же интерфейс, но никогда не запускает процессы, не выполняет надзор и не пытается управлять окнами. Explorer guard, keyboard guard, авторизация и интерфейс киоска запускаются в обычном порядке.

## Интерфейс

В состоянии настройки карточка разрешенного приложения показывает:

- имя: «Не выбрано»;
- состояние: «Не настроено»;
- пояснение: «Разблокируйте режим и выберите разрешенное приложение.»;
- надзор: «Надзор: ожидает настройки».

Оператор видит только кнопку «Разблокировать». Выбор файла недоступен до авторизации. После успешной авторизации используется существующая кнопка «Изменить приложение». Кнопка остановки/запуска надзора не отображается, пока приложение не настроено.

## Выбор и сохранение

Configurator запускается существующим механизмом повышения прав Windows. Он загружает структурно корректную конфигурацию даже при старом отсутствующем EXE, показывает системный диалог выбора и принимает только существующий файл с расширением `.exe`.

После выбора Configurator атомарно сохраняет:

- `allowedApplication.path`;
- `allowedApplication.workingDirectory`;
- `allowedApplication.configured: true`.

После завершения Configurator текущая kiosk-сессия перечитывает JSON, создает обычный supervisor, заменяет `UnconfiguredApplication` и запускает выбранный EXE. Отмена выбора не изменяет JSON и оставляет безопасный режим настройки.

## Персистентность и безопасность

Сохранение выполняется существующим `ConfigRepository`, включая атомарную замену и ACL с записью только для администраторов. Пароли не передаются Configurator и не записываются. Оператор не получает файловый диалог и не может выбрать произвольный EXE.

После перезапуска киоска валидный сохраненный путь используется без повторного вопроса. Повторный выбор возможен только из авторизованной админ-сессии. Если файл удален или перемещен, киоск не запускает замену и возвращается в безопасный режим настройки.

## Совместимость

Поведение реализуется симметрично в Modern и Legacy. Используются только уже имеющиеся JSON, Tk file dialog, `os.path.isfile`, UAC/административная проверка и существующий Configurator; новых Windows API не требуется.

## Проверка

1. Конфигурация с `configured: false` открывает kiosk UI без запуска разрешенного процесса.
2. Конфигурация со старым отсутствующим путем также открывает безопасный режим настройки.
3. До авторизации действие выбора отсутствует.
4. После авторизации Configurator может заменить отсутствующий старый путь.
5. Отмена не изменяет файл.
6. Успешный выбор сохраняет `configured: true`, путь и рабочую папку.
7. Текущая сессия запускает ровно один экземпляр выбранного EXE.
8. Следующий запуск использует сохраненный EXE без повторного выбора.
9. Modern, Legacy и parity-тесты проходят полностью.
10. Оба комплекта EXE пересобираются; после живых тестов Explorer и рабочий стол восстанавливаются.
